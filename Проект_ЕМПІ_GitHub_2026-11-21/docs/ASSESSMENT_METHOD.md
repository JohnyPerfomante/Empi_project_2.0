# Методика змістової перевірки відповідей

Версія алгоритму **2.0.0**. На сайті відкрийте **Методика перевірки** (`/methodology`). У картці відповіді викладача розгорніть **Розрахунок і порівняння еталонів**: там наведено всі метрики, вибраний еталон, підстановку чисел і параметри саме цього аналізу.

## Еталони та довжина

Публікація потребує щонайменше **двох різних еталонів**. Зміна регістру, пробілів чи пунктуації не робить копію другим еталоном. Через API можна підготувати чернетку з одним еталоном, але її публікація відхиляється до доповнення. Непідтверджені варіації не беруть участі в аналізі й не замінюють обов’язкові еталони.

Працюють локальні багатомовна `paraphrase-multilingual-mpnet-base-v2` та українська Stanza. Hash-провайдер призначений виключно для `APP_ENV=test`.

**Кількість символів не входить до формули відповідності.** Довжина перевіряється як умова допустимого введення, а не ознака правильності. Сторонній текст не отримує бонусу за обсяг.

## 1 Семантична подібність

Модель створює u = E(A) для відповіді та v_j = E(R_j) для еталона або затвердженої варіації:

```text
S_j = clip((u · v_j) / (||u|| · ||v_j||), 0, 1)
```

Для нульового вектора S_j = 0. Обмеження від’ємного значення нулем є правилом проєкту. Довгі тексти розбиваються за токенами; представлення частин усереднюються та нормалізуються.

Джерела: [Reimers і Gurevych 2019 — Sentence-BERT](https://aclanthology.org/D19-1410/), [офіційна документація Sentence Transformers про STS](https://www.sbert.net/docs/sentence_transformer/usage/semantic_textual_similarity.html), [картка використаної 768-вимірної моделі](https://huggingface.co/sentence-transformers/paraphrase-multilingual-mpnet-base-v2). Це джерела про представлення та порівняння текстів, а не універсальну готову формулу виставлення оцінки студенту.

## 2 Лексична подібність

Stanza виконує токенізацію та лематизацію. Для множин змістових лем T(A), T(R_j):

```text
L_j = |T(A) ∩ T(R_j)| / |T(A) ∪ T(R_j)|
```

Для порожнього об’єднання L_j = 0. Відсіюються PUNCT, SYM, ADP, AUX, CCONJ, SCONJ, DET, PRON, PART; маркери заперечення зберігаються. Повторення слова не збільшує потужність множини.

Джерела: коефіцієнт Жаккара у [Manning, Raghavan і Schütze — Introduction to Information Retrieval 2008](https://nlp.stanford.edu/IR-book/html/htmledition/near-duplicates-and-shingling-1.html); морфологія у [Qi et al. 2020 — Stanza](https://aclanthology.org/2020.acl-demos.14/). Множини саме лем і перелік відсіяних частин мови — адаптація проєкту.

## 3 Покриття понять

Викладач задає поняття, синоніми та ваги w_i > 0. I_i = 1, якщо у відповіді знайдено поняття або синонім як послідовність лем або точних словоформ, інакше 0. Точні словоформи запобігають хибному пропуску через неоднозначну лематизацію:

```text
C_j = Σ_i(w_i · I_i) / Σ_i(w_i)
```

Без понять C_j = null. Це **власна зважена рубрика проєкту**, а не формула оцінювання з публікації SBERT.

## 4 Поєднання метрик

```text
F_j = a·S_j + b·L_j + c·C_j,  a+b+c = 1
Без понять: F_j = (a·S_j + b·L_j) / (a+b)
```

Початкові ваги: a = 0.72, b = 0.08, c = 0.20. Без рубрики понять дві наявні метрики перенормовуються. Кожний аналіз зберігає знімок використаних параметрів.

При S = 0.85, L = 0.50, C = 0.75:

```text
F = 0.72·0.85 + 0.08·0.50 + 0.20·0.75 = 0.802
```

Комбінація, ваги й пороги — **інженерне рішення цього проєкту на основі зваженого середнього**. Публікації про окремі метрики не доводять оптимальність цих коефіцієнтів. Потрібне калібрування на незалежному корпусі з розміткою викладачів. F є індексом відповідності, а не доведеною ймовірністю правильності.

## 5 Кілька еталонів

```text
j* = argmax_j F_j
F = F_j*
```

Повні S_j, L_j, C_j та F_j спочатку обчислюються для кожного кандидата. За рівності F_j порівнюються S_j, потім L_j. Поняття беруться з рубрики еталона; затверджена варіація успадковує їх. Критичні правила з усіх еталонів питання застосовуються до всіх кандидатів, щоб альтернативний еталон не дозволяв обійти суперечність. Версія 1.0.0 спочатку вибирала кандидата лише за семантикою; версія 2.0.0 вибирає найбільший повний індекс і зберігає всі порівняння.

## Категорії та ручне рішення

1. Критична суперечність або F < T_low → LOW_MATCH.
2. Пропущене обов’язкове поняття, нове заперечення або F < T_high → NEEDS_REVIEW.
3. Решта → HIGH_MATCH.

Початкові пороги 0.39 та 0.79; курс може їх перевизначати. Заперечення є сигналом до перегляду, а не універсальним доказом помилки. Правила суперечностей задає викладач. Остаточне рішення про зарахування залишається за ним.

## Відтворення та історія

```bash
docker compose exec -T worker python -m scripts.verify_review
docker compose exec -T worker python -m scripts.verify_reference_materials
```

Сценарій використовує справжню модель для перефразування, стороннього тексту тієї самої довжини, довгої відповіді не за темою, заперечення та другого еталона. Друга команда додатково перевіряє, що кожен зі 100 навчальних еталонів задовольняє власну рубрику на реальній українській морфології. Для цієї самоперевірки семантична подібність тексту із собою дорівнює 1. Це діагностичні приклади, а не незалежний вимір загальної точності. Модульні тести перевіряють арифметику й вибір за повним індексом.

Попередні результати не перезаписуються. Для старого подання натисніть **Повторити аналіз**: новий результат 2.0.0 додається до історії, а попередні рішення зберігаються.

## Викладачі дисциплін

Сім демонстраційних дисциплін мають сім окремих акаунтів. `teacher@demo.edu.ua` залишається викладачем операційних систем. Інші логіни наведено в README. Курси, питання, відповіді та звіти обмежуються активними призначеннями. Адміністратор керує ними в картці курсу; студент бачить викладача у списку та картці дисципліни.

За потреби закладу можна призначати кількох викладачів курсу або кілька курсів одному викладачу. Демодані більше не надають одному акаунту всі дисципліни автоматично. Історичне авторство, роботи та рішення не видаляються.
